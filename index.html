03 / Field notes

Troubleshooting
notes.

A few problems I've worked through, including the wrong turns and the useful things they taught me.

01

Investigating a misleading Wazuh alert

+

Twenty-seven seconds after I enrolled a new Ubuntu agent, Wazuh fired "Trojaned version of /usr/bin/md5sum", thirty-two times. Instead of muting it, I verified the binary against the package database (clean), then read the signature itself: the legacy trojan check greps binaries for strings like "bash" and "/dev/". Ubuntu 25.10 ships the Rust rewrite of coreutils, one multicall binary with exactly those strings embedded. False positive. Tuned the check for that host and documented the signature mismatch.

  • Wazuh
  • rootcheck
  • Ubuntu 25.10
02

Finding the missing Grafana notification

+

Grafana said my storage alerts were firing. My phone said nothing. The webhook to my self-hosted ntfy server was returning 403 even though the token was correct. Root cause: Grafana's webhook contact point wants its bearer-auth keys in snake_case, and camelCase keys are silently ignored, so every request went out with no auth header at all. Two-line fix, plus a lesson that stuck: test the delivery path end to end. A green alert rule means nothing if nobody hears it.

  • Grafana
  • ntfy
  • alerting
03

Getting a firewall detection rule working

+

I wanted OPNsense port scans flagged in Wazuh, so I wrote a custom decoder. It crashed the manager: OSSEC regex is its own engine, not PCRE. My first rule crashed it again: "action" is a static field with dedicated match syntax. Third pass worked, and taught the real lesson: the stock ruleset already decodes firewall logs, so the right move was two small rules on top. One gives visibility on blocked traffic; one escalates forty blocks in sixty seconds from a single source to a level-10 alert, mapped to MITRE T1046, network service scanning.

  • Wazuh rules
  • OPNsense
  • MITRE ATT&CK
04

Giving the homelab a resource cleanup

+

A higher electricity bill sent me back to Proxmox and my cluster metrics. I'd moved services and tried new ones, but left some of the old workloads running. I retired two unused VMs, scaled unused Kubernetes deployments to zero, and tuned monitoring intervals, application workers and memory settings against actual usage. The cleanup freed about 1.7 GB of pod memory and removed 16 GB of VM allocations. It was a useful reminder to revisit what I deploy: getting a service running is one part of the job; deciding whether it still needs to run is another.

  • Proxmox
  • Kubernetes
  • Resource tuning
